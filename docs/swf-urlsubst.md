# Finite SWF URL-rewrite utility — actual output, not an AVM player

`swf-urlsubst.py` now **produces a rewritten SWF**, rather than only identifying ActionRecord headers. Its declared profile is **uncompressed FWS v1–7, at most 2,000,000 source bytes / 4,000,000 output bytes**, with one to 32 ASCII `-v NAME VALUE` substitutions (up to 1,024 bytes each). It parses SWF tag/End boundaries, nested sprite timelines, `ActionGetURL` byte lengths and two NUL strings, button records, and `DefineButton2` condition-action offsets. It rewrites literal GetURL strings inside `DoAction`, `DefineButton`, `DefineButton2`, and nested `DefineSprite` tags; recomputes action/tag/file lengths, condition-action offsets, and preserves non-URL tag payloads. A bounded SWF structural reader independently validates the source and transformed top-level/nested tag counts and frame counts. It **does not execute AVM1**, follow any URL, play/render a movie, or decode opaque shape/audio bytes.

## Pinned external reference and actual input→output checks

The user-specified [SDK mirror at commit `bb8536a8f564510f979eb8e09924bc259651a0a9`](https://github.com/SpcFORK/Macromedia-Flash-SDK/tree/bb8536a8f564510f979eb8e09924bc259651a0a9/urlsubst) contains `urlsubst.cpp` and `demo/src.swf`. The checked source was **36,073 bytes**, SHA-256 `cb120ffac9b04fecf3546506fb736be9682c893a547cdbbd4b3351f096c06baf`; the demo input was **599 bytes**, SHA-256 `eaff967749b061e9ae8505f2582bf784c6274786d5764d4e9b3582499b625f24`. Both matched the commit's Git blob SHA-1 after bounded HTTPS reads; neither is in the source delivery. A *local copy outside the checkout* received only Linux portability edits: map `stricmp` to `strcasecmp`, `_fdopen` to `fdopen`, `_fileno` to `fileno`, and declare a historical MSVC `for`-scoped `found` boolean outside its loop. The patched reference source SHA-256 was `ee0b58251de5425c1ffa7ca4f17986af38de0cf4933dc84ffca6bffe9c8f832c`; `g++ -std=gnu++98 -O0 -w` produced a local executable, never included in this repository. The SDK's `demo/test.bat` was **read as a command reference, not executed**; no archived BAT/PHP/EXE was run.

The local SDK reference command used exactly its demo variables `-v A '57859;0;0;120316' -v B 'http://www.macromedia.com'` on its checked SWF. It exited **0**, wrote a **551-byte** FWS with a repaired size header, and changed three button GetURL actions (two tracking links, one substituted window link). Reference output SHA-256: `7ca1878c4989357dbb9cb50b683e1dd95a72d84bd6c7d07ebfd97f9fab3a4dc6`. The Magnolia CLI independently wrote **the same 551 bytes, byte for byte**, exited **0**, and reported three substitutions, two historical suffix drops. A 141-byte **independently constructed synthetic input** with top-level DoAction, button-v1, button-v2, sprite action, both URL and window substitutions, and an opaque extended-length header yielded **168 byte-identical output bytes** against the local SDK executable (SHA-256 `9360dcb4034f16e0a397f42c289bc67732f2a3b8052c52a2858aa7162ef49601`). A separate **two-condition Button2** checks relocated offsets when URL lengths change; both local executables produced the **same 95 output bytes**, SHA-256 `a6dfb9f0c49975a562e27f8d1cfdd27c92afdd551a174a1f10eb661ab09da709`. The source/test fixture generator stays in Magnolia; the external SDK source and binaries are not vendored.

The SDK's observed historical string routine **drops any suffix following the first `$NAME$` marker** in a URL or window; the demo's two `?http...` fallback suffixes disappear. The finite writer intentionally replicates that observation, explicitly counts the drops, and rejects unknown/broken/multiple markers instead of silently deleting their values. This is **historical compatibility for the tested profile**, not a promise of desired URL semantics on every possible SWF. It canonicalizes tag-header widths as the SDK reference did. It currently refuses CWS/ZWS, v8+, AS3, DoInitAction, clip-action-bearing PlaceObject2/3, dynamic `GetURL2`, and unknown/branching action opcodes in a stream whose literal URL changes (byte-offset recalculation would be unsound). Depth, tag, action and output caps are enforced. Unsupported or malformed bytes and a mismatched `--expect-sha256` fail **before writing or replacing the destination**, with exit **2**; no remote URL, executable, sound or script is invoked by the writer.

## Reproduce without external SDK bytes in the checkout

```sh
# With your separately obtained, SHA-256-checked FWS, not the unrelated SWF5 upload:
timeout --signal=TERM --kill-after=2s 10s python3 swf-urlsubst.py \
  -i /path/to/src.swf -o /path/to/dst.swf \
  --expect-sha256 eaff967749b061e9ae8505f2582bf784c6274786d5764d4e9b3582499b625f24 \
  -v A '57859;0;0;120316' -v B 'http://www.macromedia.com'

# All synthetic, refusal and optional pinned SDK-demo regression tests:
timeout --signal=TERM --kill-after=2s 20s python3 -m unittest -v test/swf_urlsubst_test.py
```

The optional 599-byte demo test skips only when those externally cached original bytes are absent; three synthetic **reference-hash** gates and all other tests remain runnable offline. This utility's end-to-end **specified input→output slice** is complete; the SDK's other four utilities, arbitrary SWFs, Flash 2 player, AVM1/AVM2 runtimes, uploaded SWF audio/timeline, and `.fla` export are **not** made functional by it. It is a Python CLI for the named historical utility's task, **not** an Oak ActionScript engine or the completion of [ActionScript TODO.md](ActionScript TODO roadmap).
