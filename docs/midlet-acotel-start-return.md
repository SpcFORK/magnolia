# Original Acotel `startApp()` returned — worker deliberately not run in Magnolia

**Progress on unchanged original bytecode, NOT a playable Java ME game.** The original-only verification driver [`midlet-acotel-checkpoints.oak`](../midlet-acotel-checkpoints.oak) offers `--sequence acotel-start-scheduled` over the [reusable `start-deferred` MIDP boundary](midlet-reusable-checkpoints.md); the general `midlet.oak` CLI has no game-specific sequence. This test route runs the original `ACO_XmasGifts_s` constructor and **its actual `startApp()`**, which calls the original `DS_Effects._mth9d()`: it requests the original Canvas, creates a `Thread(DS_Effects)`, checks `isAlive()`, calls `Thread.start()` and returns. Magnolia takes a **deterministic boundary immediately after that start request**. It does **not** enter the original `DS_Effects.run()` or `paint()`, select a physical/device screen, render a frame, deliver keypad/softkey input, or play the game. `Thread.start` sets a *logical* started/queued worker; **no Runnable executes in this Magnolia route**. The original offscreen image is still the uniformly opaque-black constructor image (30,976 ARGB pixels; SHA-256 `582076772019e80f7184d6b85a32c546dbb60b88c72dbd4ca84effec1a6647f0`). Magnolia charges **18,957 steps including construction**, 30 after the [separate constructor-only gate](midlet-acotel-constructor.md). The [three direct Canvas key callbacks](midlet-acotel-direct-keys.md) remain a different *unstarted*, unselected route, not part of this `startApp` run.

A separately compiled observer invoked the **same original game method** on the unchanged original 50,594-byte JAR in real MicroEmulator 2.0.4 under JDK 11 `-Xverify:all`. Before calling it, the proxy verified the original unselected/black constructor state, `Fine` command and listener identity. After the original `startApp()` returned, the real emulator's worker was alive; the emulator asynchronously selected the Canvas, then its **real worker drew a multicolor offscreen image** (317 colors in the saved bounded sample). Immediate `Display.getCurrent()` after return is a **race**, so the observer waits for selection under a finite deadline; it does not assert a fixed tick or frame hash. Magnolia records only a *logical `Display.setCurrent` request*, not a selected device. **Reference worker execution and pixels deliberately differ from Magnolia's deferred, black worker state**; this gate compares actual original method invocation, constructor identity, command and the worker-start request, **not** worker execution, equivalent scheduling or displayed/pixel states. An emulator offscreen Image is not an actual-device screenshot.

The [SHA-pinned executable gate](../midlet-acotel-start-oracle.py) checks the original JAR (`c24e61a416616a036b537957ec9b0687ad08f9fceae18e4d06336883ec8c3040`) and MicroEmulator (`dbd5f3eb8365d3e839d6a203149e0e3776fc1a0585e16ac1fc23f76c9fcae1c6`) **outside** the checkout before launching any child. The original-only verification driver and its test profile require this unchanged JAR, entry, `a,b1,s0` resources, explicitly supplied 31,119,560-byte **constant memory snapshot** and no paint/service flag. Separately, the reusable native linker ties its explicitly SHA-pinned local JAR to the exact input class bytes, and the selected-method runtime enforces the isolated 50,000-step maximum, correct snapshot, no paint and no retained worker continuation. Original-program hashes and identity are **verification expectations**, not VM behavior. Only the original constructor and startApp closure are preflighted; the unrun `run`/`paint` bodies are **not** accepted as executable by this program image. No retained session can later execute those bodies. This is a scheduling *stop point*, not a general thread scheduler, memory/GC model, MIDP handset or Java SE Applet admission.

Five changed/profile/default inputs (same-size ZIP-valid altered JAR, wrong memory, paint flag, missing resource and ordinary lifecycle) refuse before original construction. An **18,930-step** cap refuses **during original `startApp()` after its 18,927-step constructor**, not after a completed startup. The [low-level smoke](../midlet-acotel-start-smoke.oak) also refuses missing host capability, a different method, retained continuation, wrong snapshot and unlinked paint **at zero guest steps**, and confirms no `run()`/`paint()` bodies or post-return session. No negative produces a successful game/frame record. Five new Python tests (including a fresh live differential and changed-JAR/no-report-overwrite check) and the ten cross-media-census tests passed; the census **links, does not re-execute**, this original-method checkpoint in [its report](media-blockers-current.json).
