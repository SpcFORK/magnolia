# Bounded Java ME Image and local PNG resource slice

**Status of this image slice: a same-bytecode, independently checked owned MIDlet fixture executes inside Magnolia; the original Acotel game's startup/painting does not.** A later [separate SHA-pinned original-constructor-only differential](midlet-acotel-constructor.md) executes the game's unchanged constructor and compares its uniformly black unselected image; a [further direct-key differential](midlet-acotel-direct-keys.md) invokes three original Canvas key callbacks on that object. Neither starts or renders gameplay. This work connects selected local JAR resources to the *separate* MIDlet preflight/runtime, rather than merely decoding files with an independent tool. The unchanged 50,594-byte Acotel JAR (SHA-256 `c24e61a416616a036b537957ec9fceae18e4d06336883ec8c3040`) is still refused before its constructor/output **on the ordinary lifecycle route**, now at **`java/lang/Runtime`** after the separately checked [Random/command/thread/Canvas/blit fixtures](midlet-next-slices.md). Its previous `Image` field `_fld9` is no longer the first declaration barrier. A fresh, separate Java SE Applet *static* inventory reports **23/48 bodies, 43 first-blocker entries**; the earlier **22/48, 45** ablation snapshot is not this runtime host.

## What runs, and where

- owned model classfile and `Graphics.java` are **owned bytecode models**, rebuilt with JDK 11 `--release 8 -g:none`. Their Java methods run in the bounded Magnolia VM. owned model classfile is **only a javac type stub**: its `.class` is never shipped or loaded. The shared linker now admits **nine** exact static bridge descriptors: eight default Image/Graphics services including top-left blit, plus an explicitly opt-in `clipWidth` for a [separate one-frame Canvas fixture](midlet-paint-reference.md). The VM requires the selected MIDlet profile, and the clip method also requires that opt-in; native work is charged. Java SE applet mode cannot invoke it. The ten default shipped model classfiles are compared byte-for-byte against fresh builds by the oracles; two alternative opt-in classfiles are independently rebuilt for the one-frame gate.
- Exact implemented slice: `Image.createImage(width,height)` makes an **opaque white mutable** offscreen buffer; `Image.createImage("/simpleName")` uses an immutable indexed PNG explicitly selected from **the same local JAR**; `getWidth/getHeight/getRGB/getGraphics` and `Graphics.getColor/setColor(int)/fillRect` operate on those buffers. Color and clipped rectangles are compared to MicroEmulator's **observed** default profile; this is not a promise of all devices or PNG formats. A later [bounded blit fixture](midlet-next-slices.md) also checks top-left binary-alpha `Graphics.drawImage` offscreen. Other image copies/regions, alpha regimes, Graphics methods, text glyph painting and general file/URL classloading remain unimplemented and are not silently mapped to AWT.
- `midlet.oak run --entry local.jar --class ImageResourceMIDlet --resources a,b1,s0 --sequence start --json` first checks the **classes and assets are from the same JAR**, explicitly enumerates at most 40 simple resource names, validates the selected local ZIP members/CRCs/descriptors and decodes indexed PNG chunks, zlib and pixels **before any guest constructor/output**. `--resources` on `.class`, a JAD, a URL, duplicate/unsafe names or a missing/corrupt selected asset refuses. No JAR PNGs are guessed from string constants, no disk/network URL is followed, and dynamically requested names not in the explicit selection raise a catchable `IOException` only within the supported profile. The source JAR, reference emulator and actual resource bytes are not vendored.
- Bounds: JAR ≤1 MiB, 1–8 guest classes ≤512 KiB total, selected member ≤64 KiB; indexed non-interlaced PNG type 3/depth 1,2,4,8 only; image width ≤512, height ≤256, area ≤65,536, predecoded assets ≤100,000 pixels; native Image instances ≤131,072 cumulative pixels and ≤262,144 cumulative read/write/allocation work cells, metered against the existing **10,000 VM-step** budget; a single JVM array ≤4,096 elements. The other original MIDlet restrictions remain.

## Independent positive and negative gates

`midlet-png-oracle.py` invokes **real MicroEmulator 2.0.4 `Image.createImage/getRGB`** on *all 34 unchanged original JAR PNGs*; Magnolia's standalone local-JAR PNG decoder independently matches **34/34 ARGB hashes, geometry, transparency counts and 63,372 total pixels**. Two additional **synthetic** 8-bit/five-filter and 2-bit/split-IDAT PNGs match a JDK 11 `ImageIO` decoder, with **ten** malformed/pin ZIP/PNG pre-output refusals. This decoder comparison does **not** say the original game's classes ran in Magnolia. Metadata: [`midlet-original-png-reference.json`](midlet-original-png-reference.json).

`midlet-image-oracle.py` compiles `test/fixtures/midlet-image/ImageResourceMIDlet.java` **once against the pinned real MicroEmulator API** (not Magnolia's API). The exact resulting fixture classfiles are separately executed by real MicroEmulator and Magnolia. A local test JAR combines those owned classes with **unchanged `a`, `b1`, `s0` PNG bytes** from the pinned game. A bounded reference harness waits for the real display selection; native Magnolia requests the same Canvas but does not paint it. The **24-line** trace matches exactly: dimensions **36×14, 250×144, 25×32**, sampled PNG pixels, immutable-image `getGraphics` exception, fresh mutable white pixels (`-1`), initial Graphics color `0`, full 32-bit `setColor` readback and clipped fill, zero-width `IllegalArgumentException`, and a catchable missing-resource `IOException`. Magnolia used **941** cumulative VM steps in the refreshed ten-model start-only run (formerly 937 with eight models). A **second JAR containing all 34 unchanged original PNGs** also preflights every explicitly selected image and produces the same fixture trace/step count; corrupting the **unused last asset `s31`** fails before any constructor/output. Nine pre-output refusals cover that late CRC, missing resource, corrupted used PNG CRC, duplicate/traversal JAR member, duplicate resource selection, wrong Image member, `.class --resources` and a Java SE Applet attempting to invoke the MIDP-only bridge. Metadata: [`midlet-image-resource-reference.json`](midlet-image-resource-reference.json).

Reproduce from the repository root with the pinned reference artifacts **outside the checkout** and an independently built Magnolia binary:

```sh
timeout --signal=TERM --kill-after=2s 150s python3 midlet-png-oracle.py \
  --magnolia /path/to/magnolia \
  --microemu /path/to/microemulator-2.0.4.jar \
  --jar /path/to/ACO_XmasGifts_s.jar \
  --output midlet-original-png-reference.json

timeout --signal=TERM --kill-after=2s 90s python3 midlet-image-oracle.py \
  --magnolia /path/to/magnolia \
  --microemu /path/to/microemulator-2.0.4.jar \
  --original-jar /path/to/ACO_XmasGifts_s.jar \
  --output midlet-image-resource-reference.json
```
