# Historic media static reconnaissance — not a functional-media pass

**User acceptance correction:** “parse their purpose” means **completely functional: the media/program performs the task it was designed to do**. This report does **not** satisfy that requirement. It is limited diagnostic groundwork for a future functional player/exporter/runtime gate. This checkpoint uses the three byte-pinned, user-supplied uploads already inventoried in [`historic-upload-inventory.json`](historic-upload-inventory.json). [`historic-media-purpose.py`](../historic-media-purpose.py) checks their hashes, ZIP CRC and size limits **before** reading source, then inspects selected SWF ActionRecord envelopes, OLE Compound File directory/stream chains, and only a fixed literal chart grammar. It writes a [metadata-only report](historic-media-purpose.json) after successful validation. It does not run AVM1/ActionScript, `PHP`/`BAT`, embedded Flash code, a JDK applet, or an executable; it does not export FLA, decode MP3, or render SWF frames. No upload bytes or SDK binary are included in the repository. **A later, separate [original AVM1 action-body gate](avm1-preloader-original.md) now executes the two sprite-11 `DoAction` payloads under a synthetic fixed host with an independent calculation and explicit refusals.** It does not turn this older *static-purpose report* into an execution trace, does not compare a Flash player, and does not play any of the 2,140 SWF frames.

## What the supplied SDK link provides

The [user-supplied Macromedia Flash SDK mirror](https://github.com/SpcFORK/Macromedia-Flash-SDK/tree/bb8536a8f564510f979eb8e09924bc259651a0a9) was originally inspected without running its binaries or copying them into Magnolia. A **later, separate [private native original-parser reference](sdk-swfparse-reference.md)** recompiled its SHA-pinned C++ source with portability-only edits and actually parsed the original SWF1 SDK demo; neither source nor binary was copied into Magnolia, and this older static-purpose reader did not run it. At commit `bb8536a8f564510f979eb8e09924bc259651a0a9`, its `JavaFlash/FlashApi.ZIP` is **85,800 bytes**, SHA-256 `fbb2149179c1c5a32bd9aa7f479a1e760e36e18dbd8e48147729ca67822932c2` — **byte-identical** to the previously pinned Java Flash 2 SDK in the [eight-input JVM corpus](archived-applet-ablation.md). The mirror also contains historical [SWF format references](https://github.com/SpcFORK/Macromedia-Flash-SDK/blob/bb8536a8f564510f979eb8e09924bc259651a0a9/Docs/SWFfilereference.html) and a [native `swfparse.cpp` sample](https://github.com/SpcFORK/Macromedia-Flash-SDK/blob/bb8536a8f564510f979eb8e09924bc259651a0a9/Parser/swfparse.cpp) showing action-code, high-bit length, End and older control-action conventions; the Java player includes a compiled `ScriptPlayer.class` (8,778 bytes; SHA-256 `4ef43f424698c0aaa1b2cc932e7d411c07008f714d001e60fee8875dbc5256a9`). That historical C++ sample handles some older actions but, for example, its printed `PushData` branch only recognizes string and float values; it does **not** establish a Flash-5 ConstantPool/Push/AVM1 reference oracle, modern audio/visual playback, or a new Oak runtime. The mirror's repository-level MIT file does not, by itself, resolve the proprietary notice on historic Macromedia material; this result does not redistribute that code.

**Separate later functional slices:** the [bounded SDK `urlsubst` tool](swf-urlsubst.md) now **writes literal-GetURL SWF output** against three independent original-SDK input→output checks; the [owned finite `swfparse` semantic dumper](sdk-swfparse-functional.md) produces actual original SWF1 demo shapes/actions/placements against a compiled original C++ parser. Neither tool is this older static upload-purpose reader or an AVM1/AVM2/movie player, and neither closes the whole SDK/Flash cohort.

The added decoder recognizes *only* the observed SWF5 `ConstantPool`, `Push`, `If`/`Jump`, `GotoFrame`/`GotoLabel`, and a short set of named stack/action opcodes, with payload/constant-index/branch-boundary limits. Unknown ActionRecords are marked **opaque**; AVM stack, scope, execution and SWF API behavior remain unverified. The bounded OLE reader checks v3 container chains, not FLA timeline semantics. The chart reader rejects any nonliteral `.push` line instead of calling text matching a general AS parser. Eight new synthetic/adversarial tests cover valid and broken branch/constant/tag records, valid and broken FAT/miniFAT/directory graphs, literal chart count/order, and no-output wrong-hash refusal. Independent earlier inventory counts and the separate `player-media-inventory.py` scanner remain useful cross-checks, not execution oracles.

## Reproduce under explicit bounds

From the Magnolia repository root, with the **user uploads kept outside it**:

```sh
timeout --signal=TERM --kill-after=2s 20s python3 -m unittest -v \
  test.historic_media_inventory_test test.historic_media_purpose_test
timeout --signal=TERM --kill-after=2s 20s python3 \
  historic-media-purpose.py \
  --swf /home/user/uploads/asdf.swf.txt \
  --fla-bundle /home/user/uploads/rapper_rhythm.zip.txt \
  --flic-zip /home/user/uploads/moonclouds.zip.txt \
  --output historic-media-purpose.json
```

These are **diagnostic static gates only, not the user's functional acceptance gate or full blocker closure**. Across the wider historical corpus, the separate archived [JVM/SWF report](archived-applet-ablation.md), [Falstad/Jmol/Arc/Blink gates](later-applet-corpus.md), [Java Flash and native player assessment](flash-artifacts.md), [Acotel MIDlet intake](acotel-midlet-ablation.md), and [finite MIDlet fixture lifecycle](midlet-finite-runtime.md) still distinguish format, selected method, full player, and refusal. The linked Rapper executable ZIP was not obtained, so its contents cannot be asserted or parsed from this project ZIP. Open work includes general AVM1/AVM2 execution beyond the separate direct preloader slice; SWF shapes/sounds/frame events; an independently verified FLA importer/exporter and generic FLI/FLC codecs; Java Flash 2 host/AWT/media compatibility; whole Falstad/Jmol/Blink/Arc applet runtime and rendering; complete CLDC/MIDP Acotel libraries; and rights for redistribution. **No claim that all historic media run or all blockers are fixed follows from this static evidence.**
