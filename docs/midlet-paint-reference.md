# One opt-in MIDP Canvas paint — owned bytecode, not the Acotel game

**Narrow positive gate:** with `--canvas-paint --sequence start`, Magnolia now executes the *same unchanged owned* `PaintSliceMIDlet` classfiles that JDK 11 `-Xverify:all` ran against **real MicroEmulator 2.0.4**. The fixture calls `Canvas.repaint()` while detached, selects its Canvas, then the finite native host delivers **one** post-`startApp` `showNotify()` and `paint(Graphics)` callback. The guest uses `getClipWidth()`, fills a 176×176 black surface and draws a 16×9 red rectangle. Three independent emulator runs and both Magnolia native entry routes (separate `.class` siblings and a local owned `.jar`) produced the same five ordered guest trace lines; the emulator's **actual cropped device Canvas** (not its 176×220 backing including 22 rows of chrome above and below) and Magnolia's modeled Canvas each contain **30,976 pixels** with identical big-endian ARGB SHA-256 `321b60d5f3feeb85c1bcf083b8f590712ccbd4d3c43b0c079e4f71bfcc50634e`. The red rectangle accounts for 144 pixels, black for 30,832. The fixture publishes the counters read by the separate emulator observer through `volatile` fields rather than relying on an unsynchronized cross-thread read. Native execution used **1,112 metered VM steps**. The fixture is **not** the original Acotel game.

The [new executable oracle](../midlet-paint-oracle.py) pins the real emulator (643,996 bytes, SHA-256 `dbd5f3eb8365d3e839d6a203149e0e3776fc1a0585e16ac1fc23f76c9fcae1c6`) and original game (50,594 bytes, SHA-256 `c24e61a416616a036b537957ec9b0687ad08f9fceae18e4d06336883ec8c3040`) **outside** the repository. It rechecks the owned [fixture source](../test/fixtures/midlet-paint/PaintSliceMIDlet.java), real-emulator observer, compiled fixture SHA-256s, and both opt-in Canvas/Graphics model sources against freshly JDK-built, byte-identical [model classfiles](../lib/midp1-paint-classes/javax/microedition/lcdui/Canvas.class). The new `ImageBridge.clipWidth(Graphics)` is a **javac-only stub descriptor** plus metered native service, not a shipped third-party class. The ordinary ten-model profile stays unchanged: the default fixture still refuses at missing `View.repaint()` before output. [Full traces, hashes, six checked refusals and remaining limits](midlet-paint-reference.json).

The opt-in route is **not** a MIDP event loop or general display implementation. It preflights the supplied concrete Canvas's **`showNotify` and `paint` bodies**, and the host-created `Image`/`Graphics` calls, *before* guest construction; a negative `Graphics.drawLine(IIII)V` fixture is refused without its `BAD:` line. Only one concrete Canvas subclass and one post-start callback are admitted **in this one-frame profile**; repeated/coalesced requests, `serviceRepaints`, `hideNotify`, selection changes, real `event-thread` scheduling, time, glyph drawing, key/softkey delivery, and a second frame have no parity claim **here**. A [separately selected two-frame owned-fixture service profile](midlet-service-reference.md) checks one additional synchronous callback, not a general MIDP queue. The `Canvas.repaint()` in the opt-in model merely records a request for this **one actual modeled paint**; unlike a silent no-op, the selected callback runs original fixture bytecode and modifies a metered pixel buffer. The default model does not gain it. This is native Oak/Magnolia only; no JS/HTML/Java generated-target claim is made.

**Unchanged Acotel remains pre-construction in Magnolia.** Without the separately supplied free-memory snapshot its first barrier is `java/lang/Runtime` in either route. The default snapshot route still first refuses at `Canvas.repaint()V`; the **opt-in paint route with the measured 31,119,560-byte snapshot** advances only to missing `Canvas.serviceRepaints()V`. It does **not** construct the original MIDlet, draw a game frame, deliver input, or close a remaining JVM TODO. The older [three-run repaint scheduler probe](midlet-repaint-reference.md) is an independent **reference-side** observation (two total paints after two selected requests and `serviceRepaints()`); it does not validate a second callback in this one-frame implementation. The later [two-frame owned fixture](midlet-service-reference.md) has its own reference, model, opt-in and refusal bounds and does not run Acotel. The [cross-media census](media-blocker-census.md) keeps those first barriers and static entries separate.

Reproduce from Magnolia root with separately obtained, hash-checked local emulator and original JAR plus an existing native Magnolia binary:

```sh
MAGNOLIA=/path/to/magnolia
MICROEMU=/path/to/microemulator-2.0.4.jar
ACOTEL=/path/to/ACO_XmasGifts_s.jar
timeout --signal=TERM --kill-after=3s 100s python3 midlet-paint-oracle.py \
  --magnolia "$MAGNOLIA" --microemu "$MICROEMU" --original-jar "$ACOTEL" \
  --output midlet-paint-reference.json
python3 -m unittest -v test/midlet_paint_oracle_test.py
```

No JAD URL, SWF, PHP/BAT/EXE, external player binary, Node package or network request is followed by this gate. The original game and real emulator are never bundled in the source tree.
