# Original Acotel Xmas Gifts: independent MIDP reference starts and draws

**This is a newly completed *reference-side* gate, not a Magnolia game run.** The unchanged original 50,594-byte `ACO_XmasGifts_s.jar` (SHA-256 `c24e61a416616a036b537957ec9b0687ad08f9fceae18e4d06336883ec8c3040`) was loaded as a **real original MIDlet** by the separate, pinned **MicroEmulator 2.0.4** (643,996 bytes; SHA-256 `dbd5f3eb8365d3e839d6a203149e0e3776fc1a0585e16ac1fc23f76c9fcae1c6`) under JDK 11 `-Xverify:all`, with a private user home and memory-only record storage. `test/historical/AcotelMicroemuReference.java` calls the emulator's `Headless` entry with the original game class name, then queries the genuine emulator's `MIDletBridge`, `Display.getCurrent()` and the original `DS_Effects._fld9` **offscreen image** via reflection. Reflection *observes* the original state; it does not replace any original game method or modify any original class. The owning harness samples seven bounded 250-ms intervals and calls `System.exit` so background game/emulator threads cannot keep the process alive. The uploaded JAD's old `MIDlet-Jar-URL` is **never read or followed**. No third-party JAR, artwork, framebuffer or emulator binary is shipped with Magnolia.

A bounded invocation **exited 0** and observed `ACO_XmasGifts_s` constructed, `DS_Effects` selected as the current `Displayable`, a 176×176 emulator LCDUI display, and a 176×176 original-game offscreen `Image` with **317–357 distinct colors** after initialization. Early animation samples included SHA-256 `bac65c402bb433e005edfae87c2b5d47eb90ef39796ef561a281c2f9cde3dc89` and `51300c12deb567adb1bf95f31a3ab5f14a82b584f39b5c1b0d619f6024a8959c` each calculated over **30,976 ARGB32 pixels** (176×176, big-endian bytes in order), copied from the actual original offscreen image with `Image.getRGB`; the independent report stores hashes and colors, **not images**. A repeated invocation also exited 0 and observed both states, but exact tick→frame timing varied. The emulator's separate device backing image has **38,720 pixels** and stayed at its own checksum; it is **not** a demonstrated on-screen rendering/pixel oracle. The externally bounded [metadata report](acotel-original-reference.json) records only those specific observations.

A direct uninstrumented `Headless --quit` probe reached the emulator entry but **timed out** because its background threads/live game do not end automatically; **that attempt was not a completed acceptance test**. The owned probe explicitly exits after a successful bounded startup observation. `acotel-original-reference.py` enforces both JAR SHA-256/byte counts before any JVM launch, compiles the owned source into a temporary directory outside this checkout, runs the emulator/JAR with per-child 8/10-second caps and a 128-MiB JVM heap, checks seven well-formed original-game observations plus a nonblank original offscreen frame, and writes only metadata after all checks. Four tests cover actual reference execution (optional when the separately cached JARs are present) and fabricated/blank/wrong-game/device/refusal cases. No `.bat`, `.php`, `.exe`, remote game URL or JAD fetch is executed.

```sh
timeout --signal=TERM --kill-after=2s 25s python3 acotel-original-reference.py \
  --jar /path/outside/checkout/ACO_XmasGifts_s.jar \
  --microemu /path/outside/checkout/microemulator-2.0.4.jar \
  --output acotel-original-reference.json
timeout --signal=TERM --kill-after=2s 35s python3 -m unittest -v \
  test/acotel_original_reference_test.py
```

**Remaining acceptance:** This offscreen-startup reference does not supply device-delivered key/command interaction, a playable score/termination trace, deterministic timing, real handset metrics, JAD provisioning, or pixel parity at the **actual display**. A separate [functional `Canvas.getGameAction` oracle](../midlet-key-action-oracle.py) matches 20 real default-device mappings and originally invoked the game's keyPress/keyRelease callbacks **on the reference side only**. A later SHA-pinned [original direct-key-method differential](midlet-acotel-direct-keys.md) now runs three unchanged `DS_Effects` callbacks **in both MicroEmulator and Magnolia** on the unselected constructor object, with matched input flags. These are direct calls, **not physical handset input or a running game**. Magnolia's **ordinary MIDlet lifecycle CLI still refuses before construction** at unmodeled `java/lang/Runtime` by default (after [Image/resources](midlet-image-profile.md) and [five independently checked owned-fixture slices](midlet-next-slices.md) moved earlier barriers). A **separate, SHA-pinned [constructor-only differential](midlet-acotel-constructor.md)** now executes the original constructor in Magnolia and compares its unselected, black offscreen state with an independent MicroEmulator proxy; it does **not** invoke the original `startApp`/`paint`/gameplay. This earlier reference-side startup report predates both the constructor and direct-key routes; its historical `magnoliaOriginalGameExecuted=false` field is not a current denial that those narrow original-byte routes exist. A [separate owned-fixture Font metric oracle](midlet-font-profile.md) executes the three game-required font sizes and directly observes the original Font fields **on the reference only**; it does not paint text or start the game in Magnolia. A [later opt-in one-frame Canvas fixture](midlet-paint-reference.md) now compares actual cropped **owned-fixture** device pixels with Magnolia's original-fixture bytecode, and a [distinct two-frame owned-fixture service gate](midlet-service-reference.md) checks one more synchronous callback. Neither runs the original game; Acotel with both virtual-memory and **one-frame** paint opt-ins still refuses `Canvas.serviceRepaints()` before construction, while the fixture-only two-frame flag requires a `triggerService()` method the game does not have. Completing the user's request requires expanding the existing **constant-snapshot** `Runtime.freeMemory` probe into a truthful bounded allocation/GC profile, and extending the narrow `Image`/offscreen `Graphics`/command/finite-task slices to the original game's full `Graphics`/Canvas/display and resource use, continuously scheduled paint/softkeys/input and font glyphs **as independently checked bounded semantics**, followed by original-game differential render/gameplay tests against the independent reference. A functioning **reference** proves the target has an intended screen/animation; it does not make Magnolia a Java ME emulator.
