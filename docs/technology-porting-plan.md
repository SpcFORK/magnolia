# Magnolia technology-porting portfolio — modules, ablations, design, plan

**Historical design snapshot (2026-10-26).** This document records the cross-technology strategy and the **earlier** eight-input ablation; its snapshot preflight and GUI statements below are not a fresh status report. Later bounded Fliplay/JDK gates, the distinct [three-input later applet report and Oracle AWT gap analysis](later-applet-corpus.md), and separate [FLA/FLI/SWF tasks](ActionScript TODO roadmap) are tracked in their own files. None of them establishes general Flash, ActionScript or AWT support. The existing work queues remain the [JVM queue](JVM TODO roadmap), [JVM acceptance plan](jvm-compatibility-plan.md), and [ActionScript queue](ActionScript TODO roadmap); static format research can proceed alongside, while execution and host parity have independent gates.

## 1. Decision and vocabulary

**Decision:** build a *portfolio of separately verified language/bytecode profiles*, sharing Magnolia's bounded input, provenance, dependency, host-capability, Builder and differential-test infrastructure. Do **not** pour JVM instructions, ActionScript values, Wasm linear memory, DEX registers and CLI types into one purportedly universal Oak AST. Keep the current Oak-based JVM bridge; add each new input frontend behind an explicit, independently tested adapter and semantic runtime. Prioritize a real reference oracle and an honest small runnable profile over large parse counts.

Use the following evidence levels in every status report, per **artifact + entry + target + profile**:

| Level | Exact claim allowed | Not implied |
| --- | --- | --- |
| F — identified | Magic/version, bounded container walk, hash, provenance and rights recorded | Parsed methods, valid program, or safe execution |
| P — parsed | Selected classes/modules/metadata read within limits | Decoded or valid executable bodies |
| D — decoded/inventoried | Bodies and *first* unsupported features enumerated; all-input `coverage` where available | Verification, transitive linking, runnable application |
| V — verified/linked | A selected reachable closure passes that profile's declared verifier, dependency and host allowlists | Behavior on all inputs or execution of unreachable methods |
| X — executed | An identified selected method/entry runs with bounded return, error, state and output | Whole archive, lifecycle, UI, media or parity with a reference |
| T — translated and compared | The *specified* output targets execute the same selected case and match an independent reference | Other Builder targets, all methods, general-purpose compilation |
| W — whole-artifact profile | Every required class/resource/entry/lifecycle and declared host service passes deterministic reference comparisons, including failures and UI/media traces | A different version, API profile, platform, or unrelated artifact |

A negative gate (rejecting an unsupported full entry **before output or file emission**) is a useful result, not a pass at level X/T/W. `inspect --check` may print `Unsupported` yet exit 0: inspect the diagnostic; all-input `coverage` is separate from selected-entry preflight. Original-byte **restore**, checked same-layout **recompile**, parsed/decompiled code, emitted source, and a runnable application are different products.

## 4. Proposed shared architecture

```text
Untrusted bytes/source + explicit entry + declared profile
  → bounded magic/container router + SHA/provenance/rights/resource manifest
  → profile frontend: JVM class/JAR/Java | AS3 source | ABC/SWF(AVM1/2)
                     | MIDlet(JVM+MIDP) | Wasm | CIL | DEX | ...
  → profile-specific parse + structural checks + versioned verification
  → selected dependency closure + exact host-capability allowlist
  → CheckedProgram envelope {profile, version, entry, source spans/offsets,
      classes/modules, resources, host imports, budgets, provenance, blockers}
  → profile-local Oak semantics/interpreter + deterministic headless host
  → ONLY tested per-profile emitters: native Oak / Builder JS / offline HTML /
      optional generated Java; later targets need their own acceptance gates
  → execution + reference trace comparison + separately specified round-trips
```

1. **Dispatch by evidence, not suffix alone.** Recognize `CAFEBABE` classes, ZIP/JAR with member/manifest rules, `FWS/CWS/ZWS` SWF, binary `\0asm`, DEX magic, and PE/ELF headers; an APK is a ZIP package with Android manifest/resources and possibly DEX or native libraries, **not** a Java JAR. A managed .NET assembly uses PE packaging but needs CLI metadata detection; a native PE player is not CIL. Local HTML/JNLP stay explicit JVM *launch descriptors*, not arbitrary browser HTML. Reject ambiguous/remote/unsafe paths and require explicit entry/profile when inference is unsafe.
2. **Reusable envelope, separate semantic IRs.** Share budgets, error/offset schema, hashes, dependency graph protocol, host service descriptors, trace recorder and Builder handoff. Keep JVM stack/category/verification and Java `String` semantics in JVM IR; AS3 `undefined`/`uint`/namespace/trait behavior in AS3 IR; Wasm memory/traps/imports, CIL generics/value types and DEX registers in their own IRs. Translation to Oak must preserve each profile's behavior; an Oak AST transform cannot replace a verifier.
3. **Make host dependencies explicit and metered.** Each admitted call/import declares owner/name/signature, initialization, effects and permissions (`clock`, deterministic scheduler, random, local resource/filesystem, network, font, graphics, audio, input). `jvm-vm-libs.oak` already demonstrates the exact-member pattern; build analogous **profile-specific** contracts rather than borrowing Java's API names for Flash or MIDP. Run a deterministic headless event/pixel/audio trace first; then separately test browser Canvas and, where needed, native GUI. Unknown effects must reject, never silently no-op.
4. **Emit only after selected-entry preflight.** Frontend and linker must either return a checked program or structured `{phase, kind, owner, method, offset/span, dependency, capability, limits}` diagnostics with no runnable file/partial application output. Whole-input inventory is an additional gate; unreachable code can still reveal portability debt. Implement JDK Java, Node JS, browser HTML, etc. **per target**; existing Oak→WAT/TS/Lua/Go/native output is not automatically an emitter for these profiles.
5. **Versioned, legal and isolated artifacts.** Pin digest/version/command/entry/source rights; keep Macromedia/Adobe/Mojang/other third-party binaries and AS3JS's unrelated `.git`/generated caches outside patches. Preserve MIT attribution only if importing AS3JS code; separately review proprietary notices on the archived Macromedia Java source. Cap input size, decompression, graph nodes, verifier work, heap, steps, output, frames and media; OS-isolate hostile reference binaries. Budgets are safeguards, **not a security sandbox**. Treat original restoration, same-layout edits and a future relocating assembler as different capabilities.

### Acceptance and ablation protocol for every admitted profile

1. **Identity and rights:** pin exact byte hash/source/license/profile/version, reproducible reference tool version, input size/decompression policy and selected entry. No proprietary binaries or copied AS3JS code without attribution/permission in patches or embedded outputs.
2. **Independent phases:** F→P→D→V→X→T→W recorded independently with class/module/method counts, first blocker plus *transitive* host dependencies, current target allowlist and explicit non-goals. Keep selected-entry and full-inventory reports distinct. Coverage differences are *diagnostic*, not a correctness score.
3. **Differential oracle:** include success, boundary, exception/error, initialization, mutable state, identity, Unicode/numeric edge, timer/resource and host traces as applicable. Compare JDK 11/25 for their declared JVM class versions; a legitimate AS3 player/runtime for AS3; a pinned Wasm conformance subset + independent runtime for Wasm; MIDP emulator, ART or `dotnet` for their respective profiles. Ruffle and AS3JS can be additional comparators but cannot silently stand in for the platform specification or whole-player evidence.
4. **Adversarial/refusal:** mutate one valid input at a time (length/CRC, descriptor/frame/branch, bytecode type, duplicate class, missing dependency, capability, budget). Verify rejection **before effects or emission** when invalid; preserve JDK-*valid* runtime errors as **dynamic** rather than overrejecting them. Re-run existing negative verifier controls so new host admissions do not weaken them.
5. **Isolated A/B ablation:** copy-only modification, hash both variants, same corpus/entry/limits; record parsed/decoded counts, changed *first* messages, selected preflight, oracle traces and target statuses. A zero delta is not proof of irrelevance; first-blocker counts are neither additive nor behavioral coverage. Proposed next A/B probes: correct multi-class closure for Jmol; image creation on Fliplay; listener/layout admission on Falstad; real monitor/scheduler for Flash; missing-class and modern-frame gates for Java 25; AS3 value coercions and Flash event API *after* a real AS3 profile exists.
6. **Release claim:** specify exact accepted format revisions, host-capability policy, entry modes, output targets, reference corpus/oracle versions and exclusions in docs. Only level W plus those conditions permits “whole applet/game” for the named input. No finite “runs all modern JARs” or generic “Flash supported” promise follows from smaller gates.

## 7. Explicit non-goals and primary references

Not part of this plan's immediate implementation: arbitrary Java 25 client execution; whole Minecraft, Flash 2 or Falstad playback; **general Fliplay beyond the separately gated Moon Clouds profile**; universal ActionScript/SWF; a working Java browser plugin; general Oak→JVM assembler; unsigned/signed-JAR rewriting without policy; running Windows projector/ELF plug-in; arbitrary APK, managed assembly or Wasm components; native x86/Win32/PPAPI translation; treating existing Builder backends as verified new-input adapters.
