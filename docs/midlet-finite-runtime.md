# Separate, finite Java ME MIDlet lifecycle probe

**This is a JVM-backed headless lifecycle slice, not a MIDP/CLDC-compliant emulator or a game player.** The normal Java SE Applet and Builder entry paths still refuse MIDlets. The new native-only `midlet.oak` route does **not** reinterpret LCDUI as AWT; it loads a deliberately small set of **owned MIDP-model classfiles** alongside caller-supplied class bytes. Ordinary lifecycle execution here is on **owned test MIDlets**; the unchanged third-party Acotel game still refuses **before its constructor on that route**. Separate SHA-pinned [constructor-only](midlet-acotel-constructor.md), [direct-key](midlet-acotel-direct-keys.md) and [original `startApp`-return](midlet-acotel-start-return.md) checkpoints execute different original bytecode boundaries. Only the third invokes `startApp()`; it defers the worker and **does not paint or play the game**. [Original-byte intake and static ablations](acotel-midlet-ablation.md) remain separate.

## Implemented and checked

- `lib/midlet.oak` requires an explicit entry class descended from `javax/microedition/midlet/MIDlet`, a public concrete entry and public no-argument constructor. Its **ordinary lifecycle** requires concrete nonstatic public/protected `startApp()V`, `pauseApp()V`, and `destroyApp(Z)V`; the [separate constructor-only mode](midlet-acotel-constructor.md) deliberately links just the original constructor and reachable calls, never delivering lifecycle callbacks. The [still-separate direct-key mode](midlet-acotel-direct-keys.md) additionally links three exact original Canvas key-method bodies without starting the game or delivering device input. A further [start-return mode](midlet-acotel-start-return.md) links only the original constructor/`startApp` closure, returning after `Thread.start()` while **not** linking or executing `DS_Effects.run`/`paint`. It checks every supplied class's fields, method descriptors and constant-pool class references, including *unreachable* references. Only exact owned `MIDlet`, `MIDletStateChangeException`, `Display`, `Displayable`, `Canvas`, `Command`, `CommandListener`, bounded offscreen `Graphics`/`Image`, and a **byte-executed default-device `Font`** plus a small CLDC-facing `java.lang`/debug `PrintStream` profile are admitted. A separate [bounded slice](midlet-next-slices.md) admits seeded `Random` and one finite synchronous metered `Thread/Runnable` task, not arbitrary Java SE threads. A spoofed Java/MIDP package class, a `DisplayFake` prefix trick, desktop AWT, ZIP/URL, other LCDUI types, and unmodeled reachable method calls refuse before construction. This is a compatibility/policy boundary, **not an OS security sandbox**.
- owned model classfile and byte-exact JDK-rebuilt `lib/midp1-classes/` contain the owned model, **not MicroEmulator's implementation**. The bytecode handles `MIDlet` construction/notifications, one-session `Display.getDisplay(MIDlet)` identity, `Display.setCurrent(Displayable)` **requested display**, a **separately oracled default-device `Canvas.getGameAction(int)`** mapping (20/20 checked keys), and a [bounded Font metrics profile](midlet-font-profile.md) (three original-game-required sizes, 285/285 measured ASCII glyph widths). An [independent Image/resource fixture](midlet-image-profile.md) also exercises three unchanged original JAR PNG members and bounded offscreen color/fill/pixels, but **not** the unchanged game's own classfiles. The later [command/geometry/blit/task gates](midlet-next-slices.md) cover bounded **logical** command/listener registration, a pinned 176×176 getter and top-left offscreen binary-alpha drawing; they do **not** provide softkey delivery or a displayed frame. In the **default model**, `Display.getCurrent`, Canvas repaint/show/paint, font glyph rasterization, general Graphics drawing or PNG formats, implicit resource discovery, physical clocks, timers, **key event delivery**, network, permissions, JAD provisioning and real display visibility remain unsupported. A later **separate [one-frame `--canvas-paint` route](midlet-paint-reference.md)** admits exactly one owned-fixture post-start `showNotify/paint` callback with full ARGB parity, **not** repeated repaint, the original game, or a visible device. A requested Canvas class name on the default route remains a logical fact, **not a rendered frame**.
- Generic `applet.compile` can opt into preflighting up to four *additional selected-method callbacks*; generic `applet-runtime.dispatchMethod` resumes a **single retained instance, static image and step budget**, accepts only compiled void/no-arg or one-int/boolean callbacks, and caps **four calls total**. The separate MIDlet controller alone scripts `startApp → pauseApp → startApp → destroyApp(true)` or start-only. Early `notifyDestroyed` ends the script; `notifyPaused` is not left latched after an explicit AMS resume. Every possible callback is linked/verified **before** any constructor prints. The Java SE Applet path still rejects the same owned fixture and the original Acotel entry.
- Resource limits: **1–8 supplied classes** and **ten owned model classes** (the javac-only `ImageBridge` stub is not shipped), ≤128 KiB per original class/≤512 KiB total; local JAR ≤1 MiB before bounded ZIP/CRC extraction, ≤40 explicitly selected indexed PNGs with the [image-specific limits](midlet-image-profile.md); **10,000 cumulative VM steps for ordinary lifecycle** (separately SHA-pinned original-constructor, direct-key and deferred-start modes each allow up to **50,000**), call depth 16, JVM arrays ≤4,096 elements, four lifecycle callbacks only in ordinary mode. The CLI has no implicit JAD/network download, no `--target` or `--output` Builder route and no browser/GPU renderer. A runtime exception or budget refusal is not a completed lifecycle. Model and original classfiles are read locally; the native interpreter itself needs **no JVM**.

## Independent reference and measured outcomes

[`midlet-finite-oracle.py`](../midlet-finite-oracle.py) verifies the **643,996-byte**, SHA-256 `dbd5f3eb8365d3e839d6a203149e0e3776fc1a0585e16ac1fc23f76c9fcae1c6` **MicroEmulator 2.0.4** artifact from [Maven Central](https://repo.maven.apache.org/maven2/org/microemu/microemulator/2.0.4/microemulator-2.0.4.jar), held **outside the project/delivery**. Reference usage follows [MicroEmulator's headless command documentation](https://github.com/tisoft/microemu/blob/master/microemulator/src/site/apt/usage.apt) and the [MIDlet lifecycle API description](https://nikita36078.github.io/J2ME_Docs/docs/midp-2.0/javax/microedition/midlet/package-summary.html). Its Java 11 `-Xverify:all` headless **real MIDP API** run uses `MIDletBridge`/`MIDletAccess` AMS callbacks, in-memory RMS and a private user home. It recompiles the owned fixture **against MicroEmulator, not Magnolia's model**, and independently rebuilds every owned model classfile. The compiled bytes must exactly match the checked-in classfiles; all child processes have ≤10-second caps and process-group termination. Optional download has a 12-second socket and 750 KiB transfer cap, and is checked against the fixed hash before execution. It never follows a JAD URL.

A **separately bounded real MicroEmulator reference** now executes the unchanged original game JAR and observes multicolor offscreen frames; it is *not* Magnolia MIDlet support or gameplay parity. ## Reproduce from the repository root

```sh
# Explicit opt-in HTTPS GET of only the hash/size-pinned reference artifact;
# omit --download-reference if it has already been cached outside the repo.
timeout --signal=TERM --kill-after=2s 65s python3 \
  midlet-finite-oracle.py \
  --magnolia /path/to/magnolia \
  --reference-jar /tmp/microemulator-2.0.4.jar \
  --download-reference \
  --acotel-jar /path/to/hash-checked/ACO_XmasGifts_s.jar \
  --output midlet-finite-reference.json

timeout --signal=TERM --kill-after=2s 10s /path/to/magnolia \
  midlet-finite-smoke.oak
# The separate native CLI also accepts a local owned fixture class plus its
# explicitly named helper; it never fetches a JAD or creates HTML/JS output:
timeout --signal=TERM --kill-after=2s 10s /path/to/magnolia \
  midlet.oak run \
  --entry test/fixtures/midlet/classes/FiniteLifecycleMIDlet.class \
  --include 'test/fixtures/midlet/classes/FiniteLifecycleMIDlet$View.class' \
  --class FiniteLifecycleMIDlet --json
# Separate game-required method: execute 20 real MIDP key mappings on both
# VMs, then check the unchanged original game's reference callback only:
timeout --signal=TERM --kill-after=2s 45s python3 \
  midlet-key-action-oracle.py --magnolia /path/to/magnolia \
  --microemu /tmp/microemulator-2.0.4.jar \
  --original-jar /path/to/hash-checked/ACO_XmasGifts_s.jar \
  --output midlet-key-action-reference.json
# Game-required Font metrics and the generic bounded ASCII String.charAt slice:
timeout --signal=TERM --kill-after=2s 35s python3 \
  midlet-font-metrics-oracle.py --magnolia /path/to/magnolia \
  --microemu /tmp/microemulator-2.0.4.jar \
  --original-jar /path/to/hash-checked/ACO_XmasGifts_s.jar \
  --output midlet-font-metrics-reference.json
timeout --signal=TERM --kill-after=2s 110s python3 \
  the string charAt oracle script --magnolia /path/to/magnolia
```

The bounded differential and smoke exited **0**, the earlier `String.valueOf(Object)` all-target oracle exited **0**, the original-byte **seven-ablation** gate exited **0** with unchanged 22/48 coverage, and six Python intake tests/four original entry-boundary checks passed. A separate **80-second** focused native applet-suite attempt ended with timeout exit **124** after only two progress markers; it is **not** a completed suite pass. The broad Builder integration and a fresh bundled-JS focused suite are also **not** claimed as passed at this checkpoint. Future work remains real CLDC-1.0/MIDP-1.0 device or emulator parity for input/render states, resource/JAD rules, protected package/capability enforcement across all routes and the original game before any gameplay claim.
