# Five bounded JVM behaviors: owned JDK differentials, not Flash playback

**Historical five-behavior checkpoint:** the selected byte-355 `jsr` refusal and 237/277, 52 static result below were correct **at this checkpoint**, but later advanced to `Semaphore.wait()V` byte 4 and 245/277, 44 after the [six further bounded gates](jvm-next-blocker-preflight.md), and then **256/277, 33** after [five more archive-derived behavior families](jvm-another-flash-blockers.md). The [later bounded wait handoff](jvm-wait-handoff-preflight.md) moved selected preflight to `Sound.stop()`/`sun.audio` and static coverage to **258/277, 31** at the wait checkpoint. The [later passive Class probe](jvm-image-decoder-class-preflight.md) moved static coverage to **259/277, 30** at that checkpoint; the [further bounded branching-finally fixture](jvm-branching-finally-preflight.md) moves current **static-only** coverage to **260/277, 29**, with selected preflight unchanged. The five owned behavior comparisons below remain separately passing; none of these checkpoints played Flash.

**Result at that checkpoint:** five distinct original-JVM **member families** are now admitted and independently checked on owned Java 8 bytecode. The original, SHA-pinned Flash 2 archive (`FlashApi.ZIP`, SHA-256 `fbb2149179c1c5a32bd9aa7f479a1e760e36e18dbd8e48147729ca67822932c2`) still **refuses selected-entry preflight before any Applet is constructed**:

```text
[applet] com/macromedia/flash/Flash.run()V at byte 355: unsupported JVM opcode 0xa8
```

Byte `0xa8` is legacy `jsr`; its `ret`/exception-flow semantics remain unsupported. The old first refusal at `System.currentTimeMillis()` byte 279 has moved, **not** been executed in the original. The whole-archive **static** inventory changed from **233/277 decoded bodies, 56 first-blocker entries** to **237/277, 52**. Four more bodies decode; a fifth previous first-blocker entry (`Flash.run`) is replaced by `jsr` in the same still-blocked body. Neither number is a remaining-runtime-defect count, a Flash frame, or a successful Flash 2/SWF5 run. Eight original selected-entry checks (four default and four with a virtual-clock epoch) reproduce exactly the same byte-355 refusal.

## Exactly what the five gates cover

| Behavior / original first blocker | Independently observed JDK 11 behavior and bounded implementation | Deliberate limit |
| --- | --- | --- |
| **1. `System.currentTimeMillis()J`**, `Flash.run()` byte 279 | An **explicit caller-selected logical epoch** (`options.virtualClockEpochMillis` or `--virtual-clock-epoch`) plus elapsed **virtual** milliseconds, returned as an exact two-limb JVM `long`. The single-task scheduler already advances virtual time only at `Thread.sleep(J)` yields (0–10,000 ms each, ≤60,000 ms cumulative), before draining one coalesced repaint. An owned real-JDK thread oracle checks **minimum elapsed 5 and 7 ms**, deadline ordering, and that the actual JDK anchor lies inside its wall-clock observation interval. Native, bundled JS, standalone Oak/JS and offline HTML match that JDK **ordering output** and independently check virtual timestamps `4294967293`, `4294967298`, `4294967305` across a 32-bit limb rollover. | **No epoch → runtime refusal**, never a host clock fallback. The epoch must be an integer in `0..4102444800000`, validated before construction; larger, fractional or string values refuse. Normal JVM work consumes no logical time. JDK wake-up latency, thread interleaving, true wall time, arbitrary threads and general timers are **not** claimed. Even with the option, original Flash **at this checkpoint** failed earlier at `jsr` preflight; see the later `wait()` refusal linked above. |
| **2. `Color.<init>(I)V`**, `Flash.update` byte 100 | All signed 32-bit packed RGB inputs produce **opaque** raster colors; high input bits are ignored. An owned JDK `BufferedImage` oracle and native/bundled JS compare four **actual** ARGB pixels: `ff223344 ffaabbcc ffffffff ff000000`. | Does not admit `Color(int,boolean)` or alpha compositing; that JDK-valid constructor refuses before Builder output. The existing `Color(int,int,int)` path remains separate. |
| **3. `IndexColorModel` palette readback**, `DisplayList` byte 41 | Exact `getMapSize()I` and `getReds/getGreens/getBlues([B)V` on an **already initialized 8-bit, 256-entry** palette. The JDK verifies construction-time channel snapshot, signed bytes, untouched extra destination cells, null `NullPointerException`, and a short destination's copied prefix **before** catchable `ArrayIndexOutOfBoundsException`. A complete valid copy is step-charged before mutation; under a short VM budget neither array nor counter changes. | No arbitrary bit depth/map size, indexed `getRGB(int)`, alpha palette or system peer model; separate JDK-valid examples refuse at runtime/preflight. The four methods are **one functional palette-readback behavior**, not four of the five gates. |
| **4. `Graphics.clipRect(IIII)V`**, original `Flash` helper byte 45 | Pixel-only **intersection** on a bounded offscreen raster `Graphics`, applied to `fillRect`, `drawRect`, centered-arrow `fillPolygon` and `drawImage`. The owned JDK `BufferedImage` fixture and native/bundled JS compare all **20 clipped 5×4 pixels** (including a source blit), plus all **42 pixels** of a clipped centered-arrow polygon, nested intersections and a disjoint clip that cannot reopen. The graphics object carries validated clip bounds; raster work is charged on the clipped rectangle. | No detached Component peer is invented. Negative-size rectangles, `setClip`, `getClipBounds`, arbitrary shapes, cloned `Graphics` and unimplemented raster text/line/arc refuse rather than rendering incorrectly. Initial JDK null clip is represented by effective image bounds **only for pixel writes**. |
| **5. `String.<init>([C)V`**, original `SParser` byte 97 | Snapshot of a real `[C` with **≤4,096 ASCII code units** including `\0`, exact JVM String identity and char/length results, a catchable null-source `NullPointerException`, and precharged copy work. JDK/native/JS/Oak/HTML agree on the same source-mutation and character-code trace. | JDK-valid non-ASCII UTF-16 and longer arrays refuse before output; `String(char[],int,int)` refuses selected preflight. This does **not** add general Java UTF-16, modified-UTF8 or arbitrary `String` constructors. |

Admission is exact in `lib/jvm-vm-libs.oak` by symbolic owner, descriptor and invocation opcode. `lib/applet-runtime.oak` implements the metered, fail-closed host paths; `lib/applet-java.oak` rejects the new methods before emitting unsupported generated Java. Builder invalid clock options also fail without artifacts. The narrower `Graphics` clip invariant required updating the existing direct raster-bounds unit test to use `_rasterGraphics()` instead of forging an `{image}` token; the unchanged partial-alpha refusal still passes.
