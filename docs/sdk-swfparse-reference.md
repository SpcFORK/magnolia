# Historical SDK C++ `swfparse` — original-program reference baseline

This is **one real native original parser run**, not a Magnolia SWF parser implementation, an AVM/Flash movie runtime, or completion of the four still-open SDK utilities. The user-requested SDK parser's historical C++ source at [`SpcFORK/Macromedia-Flash-SDK`, commit `bb8536a`](https://github.com/SpcFORK/Macromedia-Flash-SDK/tree/bb8536a8f564510f979eb8e09924bc259651a0a9/Parser) was reobtained **outside the workspace checkout**, SHA-pinned (`d06448e8da95c002ddfaeedae0d5160e70c82e3fa82f311aaea16336d007cf30`, 99,495 bytes), and privately compiled with `g++ -std=gnu++98 -w -O0 -g0 -lz`. Eight deterministic substitutions repair **only** prestandard-MSVC loop-variable lifetime and C++ string-literal constness; the altered source stays outside Magnolia and its SHA-256 is `0e472038ae9b98c706ad424219637c7167944cc7d624f3bbd64861ceac95594f`.

The original parser was fed the external unchanged SDK `urlsubst/demo/src.swf` (599 bytes, SHA-256 `eaff967749b061e9ae8505f2582bf784c6274786d5764d4e9b3582499b625f24`). It **exited 0**, produced **4,316 bytes of actual SWF text dump** (SHA-256 `cc1bc3aee8503c35d5e21ef91edbfa6763ce524522d19c4b0787b4f1592dcfdc`), printed genuine shape edge detail and three literal button GetURL strings/targets, three symbol placements, a background, frame and End. Against a **separate bounded Python SWF tag reader plus button-structure walker**, its dump agreed on **13/13 top-level tags, four shape IDs (1–4), placements (5/1, 6/4, 7/7), three button action payload lengths (107, 62, 10), and the SHA-256 of all six URL/target fields**. No links were followed. Two same-size **SHA-corrupted source/demo negatives** each exited 1 before native build/run or report output. Only the exact pinned and independently validated demo is passed to the historical 1999 parser: it is not secure against arbitrary inputs and is never used as an online/untrusted service.

The **repeatable** gate [`sdk-swfparse-reference.py`](../sdk-swfparse-reference.py) checks both external source and demo hashes *before* any original code is compiled or executed, stages them in `/var/tmp`, applies verified portability-only edits, runs the native parser with 128-MiB address-space, 2-MiB output-file and 10-second timeout caps, compares semantic output, and writes only metadata to [`sdk-swfparse-reference.json`](sdk-swfparse-reference.json) after exit 0. No third-party C++/SWF file, its textual dump or proprietary media is committed. The reference is **not** itself a Magnolia/Oak functional SWF parser; Magnolia's existing Oak tag-envelope scanner returns only counts/structure, **not** shapes/edges/actions comparable to the original dump. Rendering, audio, AVM1 and the user's unrelated SWF5's 2,140 frames remain wholly open. The SDK's mirror MIT notice does not override any separate historical proprietary notices.

```sh
cd /home/user/magnolia
python3 sdk-swfparse-reference.py \
  --source /path/outside/checkout/to/Parser/swfparse.cpp \
  --demo /path/outside/checkout/to/urlsubst/demo/src.swf \
  --output sdk-swfparse-reference.json
```

A **later separate [finite owned semantic parser/dump](sdk-swfparse-functional.md)** now actually compares all 43 original shape move/edge coordinates, style transitions, 12 button states, three exact URLs and three placements for this one real SWF1 demo with the native reference, and passes six pre-output refusals. That later result is a **bounded working parser task**, not this reference-only result.
