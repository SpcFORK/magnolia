# Magnolia JVM/applet compatibility: mediated route and staged completion plan

**Status: incremental, not a complete JVM.** This plan distinguishes a class file that can be *parsed*, a method body that can be *decoded*, a selected entry that can be *linked*, an invocation that can be *executed*, and behavior that has been *compared with a reference JVM*. None implies the next. It also separates **restoring archived original bytes** from **assembling a newly edited class**. The end goal is a self-contained Oak/JS/HTML conversion of suitable applets without an external JVM or browser-side Java runtime; Oak itself still runs under Magnolia, and optional emitted Java source needs a JDK to run.

**Later Fliplay gate (newer than the historical checkpoints below):** one original raw/ZIP Moon Clouds lifecycle now executes headlessly and matches **61/61** JDK frames; a *separate* raw-FLC offline Builder-JS Worker/Canvas viewer runs original class bytecode in Chromium and matches JDK/Node on the stated frames. The old exported-PNG HTML is **still not live**. Bounded explicit monitors have a cross-target JDK oracle. A newer **headless post-pause event** differential invokes original Fliplay key/mouse bytecode on nine host events in raw and ZIP modes with JDK parity; that **earlier headless oracle** is separate from the newer opt-in `gui-web` Worker, which forwards at most 16 validated browser keys/left-mouse inputs to the original retained bytecode; 8/8 original event states and 61/61 images match JDK under Node, and the native original GUI raw-FLC final ARGB matches JDK. Neither path implements a real AWT queue or historical window. Fliplay's two-class static inventory now decodes **35/35 bodies with zero first blockers**, which is not a whole-player claim. Java Flash selected-entry preflight still refuses at `Sound.stop()V` byte 36, unsupported `sun/audio/AudioPlayer.player`, after narrow [document/code-base/bgcolor](jvm-base-and-color-preflight.md), [detached RGB pixels](jvm-headless-rgb-preflight.md), [peerless Graphics-null JDK comparisons](jvm-peerless-graphics-preflight.md), [bounded bulk reads](jvm-bulk-stream-preflight.md), [five earlier JVM behaviors](jvm-five-blocker-preflight.md), [six further bounded original-Flash-oriented gates](jvm-next-blocker-preflight.md), [five archive-derived families](jvm-another-flash-blockers.md), a [single bounded JDK-checked wait handoff](jvm-wait-handoff-preflight.md), an [exact passive ImageDecoder Class probe](jvm-image-decoder-class-preflight.md), and [one bounded branching legacy finally](jvm-branching-finally-preflight.md); its current static inventory is **260/277 decoded bodies, 29 first-blocker entries**, and an opt-in logical clock is not wall time. The general JVM, AWT imaging/input, audio and SWF work remain open. A separately [signed 2020 Adobe ActiveX CAB](adobe-swflash-cab.md) is a Windows installer artifact, not an input that solves this JVM closure. See [current Fliplay scope](applet.md#original-fliplay-whole-lifecycle-and-live-worker-canvas) and [the live TODO](JVM TODO roadmap); older numeric results below are preserved as **dated checkpoints**, not current barriers.

## 1. Single mediator, explicit route boundaries

The existing mediator is `lib/jvm-bridge.oak`: `.class`, local `.jar`/`.zip`, isolated build-time `javac` and the smaller Oak-only `.java` frontend all feed **class bytes** into `lib/applet-class.oak`, `lib/applet-bytecode.oak`, and `lib/applet.oak`. `lib/jvm-vm-libs.oak` admits exact Java library references; `lib/applet-runtime.oak` executes the selected predecoded image within budgets. Standalone Oak inlines this Oak runtime; Builder's JS/HTML bundles the same runtime; the separate inline-preamble Java emitter must mirror its behavior. `lib/applet-api.oak` and `lib/build-applet.oak` adapt these shared operations to programmatic and Builder callers. There is **no applet implementation in Go**.

| User-facing operation | Canonical current route | What success actually establishes |
| --- | --- | --- |
| **Inspect / inventory** | `api.inspect(entry, {check?: true})`, `applet.oak inspect --check`; **all-method** `api.coverage(entry, settings)` or `applet.oak coverage --entry FILE [--json]` | Metadata; `--check` preflights the *selected reachable* program, whereas coverage scans **every** supplied class, field, declaration and body. Coverage exit status is nonzero for blockers. Neither is JVM verification nor behavioral parity. |
| **Transpile / build** | `import('build').run({entry, output, applet, inMemory?})`, `api.convert`, CLI `magnolia build` | Reachable verified image → `.oak`, Builder-bundled `.js`/`.html`, or optional self-contained interpreter-style `.java` **source**. `--no-optimize` is useful for editable instruction listings. Unsupported targets fail. |
| **Evaluate / run** | `api.compile`/`api.run`, `bridge.link`/`execute`, `applet.oak run`; emitted Oak/JS/HTML | Execute a bounded selected invocation (main, applet lifecycle, or explicit method). Ordinary `magnolia eval '1 + 2 * 3'` evaluates an **Oak expression**, not a JVM class; do not conflate it with `.class` execution. |
| **Package / restore** | `api.archive` / `applet.oak build` → `.applet.json`; `api.restoreOak` / `restoreTo` | A verified archive preserves original `.class` and, when embedded, original JAR container bytes. Packaging and recovery do **not** prove execution or produce edited bytecode. |
| **Recompile edited Oak** | `api.recompileOak`/`recompileJar`/`recompileTo`, Builder `EDITED.oak → NEW.class|NEW.jar` | Only a checked **same-layout** edit to a named, generated method list becomes a new class/JAR. A changed inline runtime, invocation, metadata, method set, switch table, unsafe operand or unmodeled opcode is rejected; the output is re-linked and should additionally pass JDK verification. This is not arbitrary Oak → Java compilation. |

The inventory uses the same parser/decoder as linking, but scans otherwise unreachable methods. It reports missing/unmodeled superclasses, interfaces and signature reference types as well as instruction/host blockers. Its `allBodiesPreflighted?` is **not** a claim that all calls resolve, bytecode frames verify, side effects match Java, or the whole archive runs. Class/ZIP size and blocker counts are capped; on oversized or malformed input it returns an explicit error. `coverage --json` is a scriptable, nonzero-on-blocker diagnostic.

## 2. Stages, dependencies and gates

Stages are ordered by dependencies, not promised release dates. A stage passes only when new behavior is implemented in Magnolia, has cross-route differential tests (including failures), remains bounded, and its documentation says exactly what works. No stage is allowed to replace an unsupported path with a fabricated result.

### Stage A — Lock the shared contract and the current subset (mostly done; continue auditing)

- Keep parser, reachability/linker, VM-library allowlist, interpreter, Oak emitter, Builder JS/HTML, Java emitter, archive and reverse assembler aligned. Make every input frontend feed **validated class bytes to the same linker** (different compilers need not emit byte-identical classes); `javac` must see only exact staged bytes of the individually validated, explicitly listed sources/helpers, with no ambient sourcepath or network lookup. The Oak-only Java subset stays explicitly bounded and selectable; `auto` may fall back to it only if build-time `javac` is unavailable.
- Use whole-input `coverage` alongside selected-entry preflight, not instead of it. Record class hashes and reproducible command/fixture oracles for each claimed target. Class versions that parse but lack supported semantics remain visibly blocked.
- **Gate:** `.class`, `.java` (both backends), `.jar` and local launch descriptors reach the same image when equivalent; malformed or missing dependencies fail; ordinary Oak Builder and `magnolia eval` remain unaffected; the focused suite passes in native Oak and bundled JS, while Builder integration and differential scripts pass in their respective native/Node/JDK environments. Update counts and regenerate sample artifacts when the inline runtime/VM contract changes.

### Stage B — Complete the core bytecode value model and verifier

- Build a typed JVM stack/local/heap representation with **category-one versus category-two slots**, 32-bit integers, signed 64-bit longs, IEEE-754 float/double including NaN/negative zero, Java string UTF-16, reference identity, initialization state, primitive/reference arrays and strict instruction boundaries. Do not store 64-bit longs as imprecise JavaScript Numbers. `wide` int/reference/long locals and signed `iinc` are implemented. A **bounded** reference-identity model gives JVM objects, arrays, ASCII String values and admitted host singletons distinct run-local IDs (capped at 1,048,576), with literals interned by content and host-created Strings given fresh IDs; it is not a full reference-subtype or UTF-16 implementation. Exact-limb `ldc2_w` **long** constants, selected long operations and conversions (including direct-limb `l2f` rounding), bounded `long[]` and `multianewarray` (including nested `[J` references), tagged IEEE `ldc2_w` **double**/float paths with supported arithmetic and primitive arrays, and a reachable-method I/A/J/F/D frame subset checking statically known array components and legal stack-shuffle widths are implemented. Full Java float/double decimal formatting/parsing, UTF-16, complete reference-subtype verification, uninitialized-reference and exception-edge verification, remaining library and class-version forms still need version-aware work. Keep legacy class-version-specific rules for JVM 45.3 separate from modern class verification.
- Validate control-flow frame merges, stack heights/types, local initialization, method descriptors, valid branch/switch targets, method/field access and call forms **before** producing runnable output. Retain conservative limits on classes, constant pools, instruction work, arrays, recursion and output. Extend the same typed IR to Java output and reverse-compiler checks; bytecode parsing alone must not become an unsafe verifier bypass.
- **Gate:** JDK-verified reference fixtures for every newly admitted opcode and boundary (overflow, conversion, NaN, two-slot dup forms, array covariance) match native Oak, standalone Oak, JS/HTML and generated Java or fail with documented bounded diagnostics. The historical player's `dconst_1` and constructor now decode in the typed subset, but no whole-player execution or rendering is inferred from that change.

### Stage C — Control flow, exceptions and legacy semantics

- Complete exception behavior **beyond the admitted slices**: tables, ordered handler search, modeled Java throwable objects/`athrow`, abrupt class initialization and targeted `finally` already have JDK/Oak/JS/HTML/Java oracles; full throwable hierarchy, all implicit VM/library failures and typed exception-edge frames remain open. The bounded `if_acmpeq`/`if_acmpne` identity branches execute without equating structurally equal values; complete verification of merges and constructor state remains missing. For older archived bytecode, extend the now-admitted **bounded, linear version-45–50 `jsr`/`ret` inliner** to any independently checked remaining forms (notably JDK-valid `wide ret`, still refused) and handle any remaining `wide` variants beyond admitted typed int/reference/long/F/D under a version-aware verifier; for newer classes, decide and document the chosen StackMapTable policy. Model monitors/threads only with a deterministic, bounded scheduler or reject their use explicitly.
- **Gate:** differential try/catch/finally, thrown-library-error, null, legacy subroutine and identity tests; failed handlers cannot be swallowed as successful output. Retain step/depth/heap/error limits on every path.

### Stage D — Expand the Oak VM-library transition layer

- Treat `jvm-vm-libs.oak` as a descriptor/opcode/version **contract**, not a name-based Java reflection shortcut. The current audited `java.awt.Point` island has mutable integer fields/limited constructors and helpers, but no AWT windowing, `Point.translate` overflow rules or double-returning `getX/getY`; those exact members still reject. Map additional `java.lang`, collections, arrays, text/encoding, I/O/resource and applet services only after audited Oak and generated-Java parity. Resolve inherited methods, interface defaults, dynamic dispatch, access checks and class initialization consistently across `.class`, `.java`, `.jar` and all output targets.
- Introduce explicit policies for filesystem, URL, clock, randomness, fonts and media resources. A self-contained deliverable must embed only permitted, size-bounded resources; network or native access may not happen implicitly during conversion or playback. Reference-JDK comparison should include stdout, returns, errors, heap/state and drawn frames, not merely a screenshot.
- **Gate:** every admitted host member has success, edge and rejection fixtures in Oak/JS/Java; no call is silently ignored. Unmodeled library classes remain per-member blockers in coverage.

### Stage E — Applet host, authentic Java Flash and broader playback

- Implement headless applet lifecycle, event queue, graphics/image/font/audio/timer semantics and resource resolution first; then map the verified host to Magnolia Web/Canvas and a separately tested native GUI backend. Preserve deterministic replay and bounded I/O. A complete AWT/Flash host cannot be inferred from a few `Graphics` drawing calls or a fresh-state `run()` method.
- On a lawfully obtained historical Macromedia Java player, run the **whole** class set through inventory, selected preflight, isolated reference-JVM execution and deterministic Flash 2 input/render tests. Only after compatible rendering/event/audio tests and legal review may one claim a self-contained player conversion; it would still **not** imply Flash 3+ or modern ActionScript compatibility. A separately supplied Rapper Rhythm ZIP must be hashed and statically inventoried before deciding whether its payload is even a JVM target.
- **Gate:** real applet behavior compares across headless Oak and browser host under identical inputs and explicit resource policy; unsupported event families fail explicitly. Do not package third-party player binaries absent rights.

### Stage F — General class output, only if separately required

- Keep original-byte restoration and **current working same-layout assembler** intact. General edited Oak → JVM output requires a real class-file writer: constant-pool relocation, branch widening/switch alignment, exception/debug attributes, verifier frames and version-appropriate access rules. Class/JAR edits must pass `java -Xverify:all`, preserve nonclass resources, and reject or deliberately re-sign cryptographically protected JARs. This is a **different compiler project**, not a minor extension of `applet-recompile.oak`.
- **Gate:** layout-changing additions/removals and edited methods run with matching behavior on both Magnolia and a reference JVM; original restore remains byte-identical and is never mislabeled a new compilation.

## 3. What a completion claim would require

“Full `.class` support” has no honest finite meaning without a **declared class-file version range, Java SE library profile, applet/desktop host profile and security/resource policy**. For an artifact-specific milestone, require zero unexplained whole-input inventory blockers, successful **selected** link and bounded execution, independent reference-JVM behavioral comparison (including errors, state, resources and UI frames), and the agreed Oak/JS/HTML/Java targets. A clean `coverage` report alone cannot pass this gate. For a general JVM-profile claim, also require all valid instructions and verification/linking rules in that stated version profile, tested library/host semantics, and cross-version corpus plus adversarial negative tests. Unsupported interfaces, threads, AWT APIs or class versions must remain explicitly out of profile until implemented. The Flash 2 Java Edition player is a separate artifact-specific gate; a future Flash or Rapper Rhythm claim requires actual inputs and rights review. No completion date is inferred from the present fixtures.

## 4. Regression matrix and stop-the-line rules

For each new opcode, library member or input feature, test: reference `javac --release 8 -g:none` plus `java -Xverify:all` where possible; native bridge `load → link → execute`; standalone Oak; Builder JS under Node and HTML in a controlled Canvas DOM; generated Java `javac`/`java`; zero-edit Oak → original class bytes; allowed same-width edit → new verified class/JAR; refused unsafe edits; `.jar` manifest/resource preservation; both Java frontends where syntax permits; and a malformed/truncated/unsupported negative case. Browser bundles may not depend on `localhost`, a JVM, or a third-party JavaScript JVM. Keep actual class-file fixture bytes and their Java sources together, with historical proprietary bytes outside the repository.

**Hard boundary:** implementation belongs in Oak/Magnolia libraries; Go may build/test the existing interpreter but not become the applet adapter. Do not promise arbitrary `.class`, Java source, AWT, Flash, or EXE/SWF support based on inspection, original restoration, a single opcode, or regenerated samples. The present budgets are safeguards, **not a sandbox** for hostile bytecode or compilers; use OS isolation for untrusted input. `applet.oak coverage` and `docs/flash-artifacts.md` are the next starting points for an artifact-specific backlog.
