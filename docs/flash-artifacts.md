### Original core bytecode actually executed, with a reference JVM oracle

[`historical-core-matrix.sh`](../historical-core-matrix.sh) verifies the original archive hash, extracts **unmodified** `Matrix.class` (SHA-256 `df934e7dce8756e79abe3360d1cea5a29818f4ed25f813ad0d1739abe8fca6c3`), `SParser.class` (`9fc21c5ec64e9daa32f163588f95d5ad18aae6cf1f73288c2932e11d882338db`) and `Rect.class` (`36e7b476cec00972cc31929a7dfb32d7ba5abb729e4356288dec8e7487110f74`), and compiles separate small Java *harness sources* against them. On JDK 11 with `-Xverify:all`, real `Matrix.<clinit>` and integer math produce `23, -2147483648, 2147483647, 11, 63, 0`; real `SParser` little-endian reads/cursor updates produce `33023, -1, -2147478988, 8`; real `Rect` containment/union/intersection with public `Point.x/y` produces 11 boolean lines. Native Magnolia executes those **same original method bytes**; standalone Oak, Builder JS/Node and generated Java match independent JDK outputs. Builder's self-contained **HTML** for both `SParser` and `Rect` runs their inline scripts in a network-free simulated DOM; this is not a real AWT window/event host. The generated Java emitter decodes modified-UTF-8 obfuscated identifiers into distinct `\uXXXX` Java escapes; that is not general non-ASCII `String` support in Oak/JS. Byte-exact original restoration is checked **separately** from execution.

One same-width Oak instruction edit in the original `SParser` unsigned read (`sipush 255` → `sipush 127`) produces a **new** `SParser.class`, checked by JDK `-Xverify:all`: the new bytecode and edited Oak both print `32895, -129, -2147478988, 8`. Independently, changing the original `Rect.Ɓ(Point)` minimum-x boundary branch from `if_icmpgt` to `if_icmpge` produces a **different JDK-verified `Rect.class`**. Two previously accepted boundary results become false in both edited Oak and its new class; Builder JS and generated Java also match. Each edited Oak separately restores **the original** class bytes, not the new ones. See harness sources, exact outputs, Fliplay comparison and reproduction steps. The class methods exercised here are parser/math/Point geometry building blocks, **not** `Flash.<init>`, lifecycle, SWF decoding/rendering, sound, complete AWT or a converted working player. This selected-path success cannot make the currently **29 static first-blocker entries** (or unvisited transitive dependencies) disappear.

The SDK repository's modern root `LICENSE` says MIT, but its historical `JavaFlash/Source/FlashApp.java` begins with a Macromedia proprietary/confidential notice. ## Implications for Magnolia Builder / Oak

- Existing class/JAR → Oak/JS/HTML/Java paths accept supported **JVM bytecode**, magic `CA FE BA BE`. They cannot execute or translate a Windows PE projector, Linux ELF PPAPI plugin, or SWF just by changing a file extension. **Original-byte restoration** remains separate from **executing selected real methods** and from the tightly scoped **edited Oak → new `.class`/unsigned `.jar`** assembler (see [applet.md](applet.md)); none makes the *whole* Java Flash player executable yet.
- Running the native player *as itself* in self-contained Oak without a system JVM or external Flash runtime would require a verified **x86 machine-code execution/translation layer**, process memory and native OS ABI, plus either a PPAPI browser host (for the `.so`) or a Win32 GUI/audio host (for the `.exe`). Supporting arbitrary SWFs through that player additionally requires its actual Flash VM, renderer, I/O, timing, and security behaviors. This is an independent, substantial native-compatibility project, **not implemented** in the applet adapter. A SWF-only converter would be a separate Flash-content path, not conversion of the Adobe native player.
- For an **uploaded** game projector, first hash and inventory ZIP entries without launching programs; inspect PE headers/resources/overlays; validate any candidate embedded `FWS`/`CWS`/`ZWS` SWF against its declared length, compression, and tag structure; identify whether the player is included or external; report the Flash/ActionScript version. Do not promise runnable Oak/JS before interpreter and host parity tests exist.
- Archival download availability is not redistribution permission. Do not check proprietary Adobe player binaries into the repo or put them into generated self-contained output without resolving rights. Untrusted executables should be handled only by static inspection or in appropriately isolated environments.
